# Float design

These mockups are the source of truth for Float's UI. When the app and a mockup disagree, change the app. Any change to the design starts here.

| File | Shows |
| --- | --- |

| `pickers.png`, `float-pickers.html` | Choosing a machine and a project (new chats only, never a branch or checkout), and the model picker across providers: favourites, provider tabs, search, disabled provider. |

## Fixed rules

- **Opaque panel, frosted input.** The panel is opaque, so the desktop never shows through. The conversation scrolls up *behind* the frosted input, and the input blurs the message text under it, as in T3's composer. The solid footer tucks under the input with concave corners. The input's top corners are drawn as solid concave ears over the scrolling content.
- **Composer text.** It matches T3's composer rhythm: 14pt text in a 1.625× line (22.75pt, T3's `leading-relaxed`), with the extra height split evenly above and below the glyphs. There's 12pt of padding above and below the text (nordbones `padding: 0.75rem 1rem`) and 20pt at the sides. The placeholder sits in the same line, so it lines up with typed text.
- **Input rim.** As in T3, the frosted input has a 1px hairline ring (foreground at about 9%) that follows its 16pt corners all the way round, so it reads as its own inset card. The input is inset 1pt from the shell's left and right edges, so a 1pt strip of solid tray separates the shell border from the rim and the two lines never merge.

- **Corner radius:** 16 for the shell, 12 for your message bubbles, 10 for cards and menus, 6 for chips.
- **Thinking loader:** the 3×3 pixel grid, 4 frames, stepping every 300 ms, followed by T3's shimmering "Thinking" text and the elapsed time. The shimmer copies T3's `live-activity-focus` (`apps/web/src/index.css`): the word in the muted colour, with a 4.5rem band of the text colour sweeping left to right every 2.2 s in 30 steps, fading in and out at 12% → 55% → 100% → 55% → 12%. With Reduce Motion, no sweep. These two are the only progress indicators.
- **Replies:** show only assistant text. Never show tool calls, with one exception: text an agent shows you through T3's `send_to_user` tool is part of the reply, in order, rendered as Markdown like any other reply text (T3 shows it the same way). Code blocks copy T3's `MarkdownCodeBlock`: radius 8, the input colour at 32% on dark, a header row with the language's file icon from T3's icon set on the left (or the language name when there's no icon) and wrap and copy buttons on the right, then the code in monospaced text in the text colour, wrapped by default. No syntax highlighting. Replies have no bubble: plain text on the tray, as in T3. Under each reply sits a muted row with the copy button first, then the time, left-aligned. One reply is everything the agent shows in one turn (its text and any `send_to_user` messages), so it gets one meta row, at the end; copy copies the whole reply. Only your own messages sit in bubbles.
- **Header:** a close button (×) at the top left, then a crumb as T3 shows a thread: the project's icon (T3's project icon when it has one, otherwise a folder) and name in the muted colour, plus " · <machine>" when the thread isn't on this Mac, then a muted slash, then the title in the text colour. A chat with no project shows just the title. Whenever a chat has a project, its name is always there: `<project> / <chat title>`, for chats started in Float and for threads reopened from T3. No status dot, except a grey one while T3 or the thread's machine is disconnected. New chat and Open in T3 sit on the right. The × hides the panel, the same as Esc; the draft and chat stay. The compact state has no header, so Esc hides it there. Quit Float lives in the menu bar cloud's right-click menu. You can drag the window by the header as well as the footer.
- **Markdown:** replies and your own messages render GitHub-flavoured Markdown as T3 does (`apps/web/src/components/ChatMarkdown.tsx` with `remark-gfm`): paragraphs, headings, bold, italic, strikethrough, inline code, links and autolinks, nested bulleted and numbered lists, task lists, blockquotes, horizontal rules, tables, and code blocks. Spacing, sizes, list markers, quote bars and table borders copy T3's `.chat-markdown` rules in `apps/web/src/index.css`, scaled to Float's 13.5pt body text. Tables scroll sideways rather than squeezing. Images show as links. Maths and `<details>` show as plain text. Partial Markdown while a reply streams (an unclosed fence or table) renders sensibly and never flickers between layouts. Parsing uses Apple's `swift-markdown` (cmark-gfm), the one allowed dependency for this.
- **Skills and commands:** as in T3's composer. Typing `$` at the start of a word opens the skills available to the chosen model's provider. Typing `/` at the start of a word opens T3's own commands, the provider's slash commands, and skills listed as `/skill:name`. `/clear`, `/side` and `/btw` only show at the start of the message. The menu spans the composer just above the input, at most 288pt tall. It uses one line per item: an icon, the name in medium weight, a muted description, and the provider's mark on the right. Items are grouped under muted headers in the `/` menu. Typing filters it, the top match sits in the selection pill with a `↵` key cap, ↑↓ move, Return or Tab picks, and Esc closes. A picked skill becomes a chip in the input (accent text on a light accent fill, radius 6) that Backspace removes whole. It's sent with the prompt the way T3 sends it. A picked command runs or inserts as T3 would. See `design/pickers.png` states 9–11.
- **Questions and approvals:** when an agent asks you something through T3's ask-user-question tool, Float shows a question card in the tray, drawn as T3 draws it (state 6): the header in sentence case, muted; "2/3" with a chevron at the top right that jumps between questions; the question in regular weight; then one row per option with a radio circle (a checkbox when several can be picked), the label, the muted description, and the number key on the right. An option's `preview` always shows under it as plain monospaced text in the muted colour, for every option at once, never only on hover. **Nothing in the card changes size on hover or keyboard movement**: hover and the highlight only tint the row, so the panel never jumps. While a question or approval waits, the run is still going, so the send ring is the red stop ring: Stop or ⌘. interrupts the run and drops the card unanswered. Number keys pick, Return confirms, and typing in the input answers in your own words when the question allows it. When there are several questions, every question after the first has a Back button (ghost style, to the left of Next or Send answer, also ⌘[) that returns to the previous question with its answer still picked. Answers are kept until you send them all, and nothing goes to T3 until the last question is confirmed. The answer goes back through T3. Tool approvals are answered in Float too (state 5): the approval card shows what the agent wants to do, with Allow (primary, ⌘↵), Deny, and a small Open in T3 link for the full request, so the run keeps going without opening T3. Approving needs a T3 credential that is broader than approve/deny (`orchestration:operate`, which can also start runs), so it's off until you turn it on once: the first approval card offers "Answer approvals in Float", which explains that in one sentence; turning it on has Float issue a dedicated credential with T3's own CLI and keep it only in the Keychain. Turning it off (in the menu bar cloud's menu) revokes it. Until it's on, and for threads on other machines, the card offers Open in T3.
- **Footer:** paperclip on the left; provider icon, model and send/stop on the right.
- **Panel size:** once a chat has a tray, the panel opens straight to its full size, even for the first message, and never grows or shrinks as messages stream in. You set that size yourself: drag the top edge to change the height, or either top corner to change the height and the width together. The bottom edge and the input stay anchored, so dragging moves only the top (and the dragged side). Grab zones: 4pt along the top edge with the up-down cursor, 10×10pt at the top corners with the diagonal cursor. Limits: height 240pt to 85% of the screen's visible height; width 420pt to 900pt. Float remembers the size. Double-clicking the top edge resets it to the default (560pt tall, today's width). The compact state, with no tray, keeps its width and never resizes.
- **Dragging:** you can drag the window by the header, the footer's empty space, and a thin strip along the top edge of the input (6pt, arrow cursor), which matters in the compact state where there's no header.
- **Pickers:** the model, project and Run on pickers keep one size and one anchor while open, whatever tab or query is showing, so they never jump. The model picker is a fixed 300×360pt and its bottom-right corner stays pinned above the model button; the list scrolls inside it. The current item sits in a filled pill in nordbones `secondary` (`#1C3349`, radius 8), as T3 marks a selected chip, with no checkmark. Hover and the keyboard highlight use the text colour at 6%. Trailing status dots line up in one column. With the search field focused, ↑↓ move the highlight through the list, Return picks the highlighted item, and Esc closes the picker (Esc closes every Float menu and picker before it hides Float). No hint rows and no ⌘1–9 tab shortcuts; click a tab to switch. In the model picker, clicking an effort segment sets that model's effort. The effort row always starts with its "Effort" label, and its segments fit inside the picker without clipping, even for long values like "Ultrathink". The model picker has no "Use T3 default" row: you always pick a specific model.
- **Context row:** for new chats, the Run on and Project chips sit in a small strip under the panel, like T3's context strip. It hugs its chips (3pt padding, 4pt between chips), 6pt below the panel, with a 12pt radius. Its fill is the panel's colour at about 94% with a light blur, plus the panel's hairline border and a soft shadow, so it reads on any wallpaper, light or dark. Chips are a 12pt icon, muted 11.5pt regular text and a small chevron, 22pt tall with a 9pt radius. No border, no outline, no text effects, no focus ring. Hover is the text colour at 6%. An open chip uses the selection pill (`#1C3349`) with text in the text colour. See `design/pickers.png` states 1 and 1b.
- **Disabled buttons:** a disabled button is always readable. A disabled primary button (for example Send answer before an option is picked, or Allow while a decision is in flight) switches to the ghost style: no fill, the panel's hairline, label in the muted colour at full opacity. Never accent-coloured text on a dimmed accent fill. It becomes the filled accent button the moment it's enabled.
- **No focus rings:** Float's own buttons, rows and chips never show macOS's blue focus ring. Keyboard focus shows the same way as hover: the text colour at 6%. The only visible focus is the caret in a text field.
- **Scroll bars:** overlay knobs only, never a track, everywhere (conversation, input, pickers, code blocks).
- **Keyboard:** ⌥Space toggles Float, Esc hides it (or closes an open picker first), Return sends, ⇧Return adds a new line, the standard editing keys work in the input (⌘A, ⌘C, ⌘X, ⌘V, ⌘Z, ⇧⌘Z), ⌘V also pastes images, ⌘N starts a new chat, ⇧⌘M opens the model picker, ⇧⌘P the project picker, ⇧⌘H the Run on picker, ⌘. stops a run.
- **Shared centre lines:** the header's × sits on the same vertical centre line as the footer's paperclip, and Open in T3 on the same line as the send ring, 21pt in from each inner edge of the shell.
